# 평가 정책 — 3단계 B

2026-10-15 사용자의 지시에 따라 judge를 **Claude Sonnet 5.5**로 고정하고 실제 수정 문장에 대한 사람 라벨링을 수행하지 않는다. **모델 고정과 사람 라벨을 쓰지 않는 결정은 이번 검증 결과를 보기 전에 정했다.** 이전의 Haiku/Sonnet 중 세 기준을 통과한 최저가 모델 선택 계획을 대체한다. 활성 설정은 [evaluation_policy.yaml](../configs/evaluation_policy.yaml)과 [stage3_protocol.yaml](../configs/stage3_protocol.yaml)이다.

## 검증과 중단 기준

| 검증 | 자료 | 통과 기준 |
|---|---|---|
| 원문 품질 선택 | 같은 문항의 서로 다른 원문 20쌍, 두 표시 순서로 총 40판정 | 사람 원점수가 높은 글 선택률 ≥70%; 동률은 오답 |
| 규칙 변형 의미 보존 | 유지 변형 40쌍 + 변화 변형 40쌍 | 보존 대 변화 Cohen's kappa ≥0.6 |

두 기준 모두 점추정치로 판정한다. 하나라도 실패하면 중단하며 모델·추론·프롬프트를 바꿔 재시험하지 않는다. 원문 비교는 문항 20개, 규칙 변형은 규칙 종류 8개를 군집으로 삼아 bootstrap 10,000회, seed=315042의 95% CI를 함께 보고한다. CI 하한을 새 통과 기준으로 쓰지 않는다. 원문 비교에서는 두 순서 모두 정답인 비율과 순서 불일치율도 보고한다.

규칙 변형의 정답은 생성 규칙에서 정하고, 원문 품질의 정답은 기존 데이터의 사람 채점값에서 얻는다. 이것은 **수정 문장의 사람 라벨**과 구분한다. 원문 쌍은 같은 문항, 사람 합계 점수 차이 16점 이상, 두 채점자의 순위 일치를 요구했다. 파일럿 10편 및 1.5단계 100편을 제외했고 원문 40편은 향후 5단계에서도 제외한다.

두 기준을 통과하면 기존 실제 수정 50쌍에 judge 판정만 저장한다. 표본은 초기 Luna 실행 26쌍과 과거 Haiku 실행 24쌍을 섞은 고정 표본이다. 사람 일치율·사람 kappa는 계산하지 않는다. 사용자가 지정한 `claude_reference_labels.csv`와 비교할 때는 ID뿐 아니라 before/after 본문 일치도 검사한다. 참고 라벨의 정확한 Claude 버전은 파일에 기록돼 있지 않다. 이 비교는 같은 Claude 계열 간 보조 참고이며 독립적인 사람 검증이나 통과 기준이 아니다.

## 판정 기준

쌍대 비교는 교정 정확도, 원문 의미 보존과 내용 추가 여부, 학습자 수준과 문체 유지를 각각 판정한 뒤 종합한다. 유창함·길이·어려운 어휘 자체를 우위로 보상하지 않는다. 수정 전 원문이 없는 서로 다른 원문 비교에서는 의미 보존은 동률, 내용 추가 여부는 판단불가로 기록한다. 전체 품질은 문항 충실성·내용·조직·표현으로 비교한다.

의미 판정은 보존 / 경미한 뉘앙스 변화 / 의미 변화와 이유, 원문에 없던 정보 추가 여부를 반환한다. 경미한 뉘앙스 변화도 이분류에서는 변화다. 프롬프트는 [judge_pairwise.md](../prompts/judge_pairwise.md), [judge_semantic.md](../prompts/judge_semantic.md)에 있다. 요청에는 작성 모델·조건·사람 점수·정답·참고 판정을 넣지 않는다.

## 실행과 비용

`claude-sonnet-5-5`, `thinking=between_tools`, `effort=low`, 도구 없음, temperature 생략, 최대 출력 2,048토큰으로 고정한다. Sonnet의 disabled 대신 도구 없는 between_tools를 사용해 답변 전 추론을 생략한다. [모델 공식 설명](https://platform.claude.com/docs/en/models/sonnet-5-5/whats-new-sonnet-5-5)

사용자가 승인한 총 예산은 **$3.00**다. 검증 120회 후 두 기준 통과 시 실제 수정 50회, 정상 경로 총 170회다. 스키마·인용 검증 실패에는 항목당 최대 두 번의 형식 수정 요청만 허용한다. 판정 결과 때문에 재요청하지 않는다. 모든 요청과 재요청은 하나의 예산 장부를 공유하고, 최대 출력 및 캐시 미적중을 가정한 금액을 먼저 확보한다. 남은 예산이 부족하면 제출하지 않는다.

검증 120건은 Messages Batch API의 50% 할인, 실제 수정 50쌍은 **일반 Messages API**를 사용한다. 실제 수정 50쌍의 일반 API 전환은 검증 결과를 보기 전 사용자의 추가 지시에 따른다. 두 경로 모두 공유 시스템 프롬프트의 1시간 캐시를 사용한다. 단가는 입력 $2/M, 출력 $10/M, 1시간 캐시 쓰기 $4/M, 읽기 $0.10/M이며 검증 Batch에만 할인 50%를 적용한다. 실제 캐시 적중 여부와 사용량은 응답에서 집계한다. 대부분의 Batch는 1시간 이내 처리되지만 각 Batch는 최대 24시간 걸릴 수 있다. [공식 가격](https://platform.claude.com/docs/en/about-claude/pricing), [Batch 처리](https://platform.claude.com/docs/en/build-with-claude/batch-processing), [캐시](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

## 해석 한계와 기존 평가 유지

**실제 수정에 대한 judge 판정은 사람으로 검증하지 않았다.** 규칙 변형을 잘 분류하고 서로 다른 원문의 사람 점수 순서를 맞히더라도, 같은 글의 수정본 비교가 타당하다고 보장하지 않는다. 규칙 80쌍은 8개 문장 틀에 이름을 바꾼 사례이므로 80개의 독립적인 언어 현상 검증이 아니다. 실제 수정 50쌍은 위험 사례를 포함한 선택 표본이므로 전체 에이전트의 의미 보존율로 해석하지 않는다. 참고 라벨과의 CI도 글 5개에 의존한다.

주 지표는 다른 계열 judge의 쌍대 비교와 의미 보존율, Kanana는 N=64 정수 평균 및 greedy 보조 지표로 유지한다. N=64의 선택은 **1.5단계 결과 이후의 결정**이며 이번 judge 선택 시점과 구분한다. 원래 글 ID 시드 규칙·원본 채점기·자질 계산·KB는 변경하지 않는다. 이번 작업은 3단계 B이며 v0.1 동결이나 5단계 반복 평가를 시작하지 않는다.
